# Modal runtime and graph-specialization research

**Ticket:** [Research Modal execution, compilation reuse, and cost semantics](https://github.com/pymc-labs/pymc-generator/issues/48)
**Retrieved:** 2026-10-13 UTC. **Repository revision:** `b941d3a222fb91475cc2b59db14281e2b6498c49`.
**Method:** source and official Modal documentation only. No install, model execution, deployment, credentials change, or paid Modal run.

## Findings

Modal **Functions/Cls**, not Sandboxes, are the initial execution primitive to evaluate for corpus generation. A `@modal.enter()` initializer runs once before a container receives inputs and `self` persists for subsequent calls handled by that individual container; it is discarded at container termination. Thus a compiled PyTensor object can be reused only within that live container/process, never assumed shared across containers. Functions autoscale and containers can scale to zero; `min_containers`, `buffer_containers`, `max_containers`, and `scaledown_window` trade cold latency for billed idle time. [Modal Functions](https://modal.com/docs/guide/functions#container-lifecycle-management), [scaling](https://modal.com/docs/guide/scale).

Modal's `map()` runs independent inputs in parallel and returns input order; `spawn_map()` is the documented durable background batch-submission route for externally persisted results. Functions normally take one input at a time; `@modal.concurrent` uses threads/tasks and Modal says it is less likely to help CPU-bound functions. [Scaling](https://modal.com/docs/guide/scale#parallel-execution-of-inputs), [batch processing](https://modal.com/docs/guide/batch-processing), [concurrency](https://modal.com/docs/guide/functions#concurrency-and-batching).

Container crashes reschedule in-flight work, configured retries rerun function failures, and map inputs retry independently. This supports stable logical task IDs and seed derivation plus idempotent persistence. A candidate protocol validates output and deduplicates publication by logical identity, but publication atomicity and concurrent-retry arbitration depend on the chosen backend and remain unresolved; these execution docs do not establish an atomic manifest primitive. [Execution semantics](https://modal.com/docs/guide/functions#execution-semantics), [retries](https://modal.com/docs/guide/retries).

The repository caches a compiled draw function **on the model instance**, keyed by output/input/mode/reference, so reuse is in-process and same-model only ([`world_model.py#L63-L164`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model.py#L63-L164)). `draw_worlds` documents `FAST_COMPILE` and this per-model reuse ([`#L2010-L2049`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model.py#L2010-L2049)).

The repository’s experimental template makes one max-size graph, passes structure as runtime data, and compiles once per shard, but explicitly is not a production drop-in ([`world_model_template.py#L1-L22`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model_template.py#L1-L22)). It rejects treatment shocks, prior conditioning, and non-fixed confounding ([`#L79-L97`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model_template.py#L79-L97)). Existing template benchmarking is candidate-draw-only and excludes acceptance filtering, retries, normalization, and serialization ([`template_vs_per_world.py#L1-L14`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/benchmarks/template_vs_per_world.py#L1-L14)).

### RNG/support limits

* Templates have padded RV shapes and a separate random schedule; identical seeds do not imply numerical draw equivalence ([`world_model_template.py#L1-L22`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model_template.py#L1-L22)).
* RV creation order is load-bearing because RNGs are reseeded by collected order; enabling live optional texture can deliberately reseed worlds ([`world_model.py#L722-L831`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/world_model.py#L722-L831)).
* Dynamic edge masking wires full chains, changing ancestor/RNG properties versus statically absent edges ([`symbolic_graph.py#L918-L924`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/symbolic_graph.py#L918-L924)).
* `max_eps_draws` amortizes compilation but changes the draw stream; reproducibility requires it fixed ([`worlds.py#L1083-L1087`](https://github.com/pymc-labs/pymc-generator/blob/b941d3a222fb91475cc2b59db14281e2b6498c49/pymc_generator/worlds.py#L1083-L1087)).

## Resources, snapshotting, and billing

Functions/Sandboxes default to 0.125 physical CPU and 128 MiB; CPU/memory are charged at the larger of request or actual use, and disk inflates memory request 20:1. [Resources](https://modal.com/docs/guide/resources). Function memory snapshots can capture initialization/JIT work but are created only for deployed Apps; snapshot creation itself adds latency and code/config changes invalidate snapshots. [Memory Snapshots](https://modal.com/docs/guide/memory-snapshots). Sandbox filesystem snapshots exclude mounted Volumes; sandbox memory snapshots are experimental and seven-day retained. [Sandbox snapshots](https://modal.com/docs/guide/sandbox-snapshots). Therefore normal Function/Cls reuse should be evaluated before snapshots; snapshotting compiler/RNG state needs explicit validation.

**Published price retrieved 2026-10-13 UTC:** standard Functions list $0.0000131/physical-core-second and $0.00000222/GiB-second; volume $0.09/GiB-month; egress $0.04/GiB. Sandbox/Notebook CPU/memory list $0.00003942/core-second and $0.00000667/GiB-second. [Pricing](https://modal.com/pricing). Modal bills application load, input processing, and by default 60 seconds after final input before scale-down; charges stop at zero containers. [Pricing FAQ](https://modal.com/pricing), [Billing](https://modal.com/docs/guide/billing). No workload cost is estimated: CPU/RAM, acceptance, retries, serialization/storage, and idle behavior are unmeasured.

## Conditional recommendations and unresolved decisions

1. **Hypothesis only:** benchmark an ordinary shard worker against a finite compatibility-key worker pool specialized by saturation×adstock family and, only when shape changes, component sets/jump capacity. Do not specialize dynamic scalar values or active counts.
2. Preserve stable logical IDs/seeds independent of scheduling, worker count, and retry; record each worker compatibility key in its manifest.
3. Before selecting a path, measure cold and steady-state accepted/persisted/usable worlds per second and dollar, including compile, rejection/top-up, retries, validation, serialization, storage, and idle time; record peak/requested resources and duplicate-publish attempts.
4. Unresolved: required parity criterion (byte parity versus distribution/schema/replay criteria); allowed template subset versus ordinary fallback; max worker count/shard size/`max_eps_draws`; resource and spending caps; persistence protocol; and whether deployment/snapshots are permitted.
