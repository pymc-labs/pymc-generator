## Actionable Task 1 findings

1. **HIGH — saved-analysis config can silently mislabel the scored population.** `studies/recovery/__main__.py:25-32` passes only `worlds` and gate thresholds; `studies/recovery/analysis.py:68-93,96-128` scores entire stored 97-row paths without checking `study.score_weeks` or `reported_weeks`, dataset seed/horizon, baseline format for bounded OLS, or the saved artifact manifest. `StudyConfig.parse({'study':{'score_weeks':[0,103]}})` succeeds, but a subsequent `saved_summary(...,kind='tv_nuts',worlds=50)` is identical to the default 7–103 result. A user can therefore request 0–103 (or another valid window) and receive 7–103 numbers without warning. Require exact legacy format/window compatibility and provenance checks (or explicitly slice a sufficiently complete input); reject unsupported windows/other mismatches before reporting, and test the negative path. This is a read-only Task 1 parity defect, not a demand to implement Task 2 generation.

2. **HIGH — unsupported generation settings can pass the purported capability preflight.** `studies/recovery/config.py:79-118` validates only supplied `edge_budget` keys, not the complete resolved direct-only graph, and accepts `n_treatments_active_range=[0,0]` even though this study requires at least one media outcome effect. `config.py:94-96` accepts `burn_in=1` with geometric lag 8; existing notebook asserts `l_max==8` with carryover burn-in (`notebooks/ols_reporting.py:2428`), while approved contract requires explicit horizon/window validation. An omitted edge budget or an omitted baseline-std range is never concretely resolved to guaranteed supported values; `config.py:119-131` enforces baseline compatibility only when a range is supplied. Resolve and validate a complete supported DGP config (or reject insufficiently specified requests), validate active-count/edge feasibility and burn-in/lag relationship, and cover defaults/omitted keys in tests before Task 2 consumes this schema. No assertion that currently unavailable generation adapters actually executed these invalid settings.

3. **MEDIUM — a manifest is treated as a complete checkpoint even if outputs are absent.** `studies/recovery/artifacts.py:70-86`: `write_manifest` writes identity to an empty directory, then `checkpoint` returns True as soon as that manifest matches, with no completion marker, expected-file inventory or hashes for outputs. In a temporary directory, immediately after `write_manifest(stage, identity('fit', ...))`, `checkpoint(stage, expected)` returned True with `['manifest.json']` as the only file. Preserve a separate initialized/partial/completed state with verified per-world output files for Task 2 resume; don't equate an identity-compatible empty or interrupted stage with completion. `tests/test_recovery_task1.py:61-74` currently asserts the incomplete state as True. This is a checkpoint contract defect now, although actual resume loops belong to Task 2.

4. **LOW — malformed nested TOML lists cause uncaught TypeError rather than ContractError.** `studies/recovery/config.py:138-143,187-190` applies `set()` before validating scalar element types. `StudyConfig.parse({'methods':{'enabled':[['ols']]}})` and `StudyConfig.parse({'methods':{'advi':{'seeds':[[1]]}}})` both raise `TypeError: unhashable type: 'list'`. Validate element types first, preserving actionable config errors; add negative tests.
